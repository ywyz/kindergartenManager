# KindergartenManager 产品功能与系统能力方向

> 文档性质：产品方向与需求拆分基线，不是实现规格、发布承诺或 GREEN 授权。
>
> 分析基线：2026-08-31，当前 `main`（以检出时实际 SHA 为准）。
> “已实现”只表示当前代码存在相应能力；目标平台、Word、MySQL、真实 AI、浏览器和生产门禁仍按
> [`docs/ROADMAP.md`](ROADMAP.md) 与固定 SHA 证据分别验收。
> 产品规划跟踪见 [Issue #55](https://github.com/ywyz/kindergartenManager/issues/55)。

## 1. 产品定位与演进原则

当前最适合的定位是“面向单园教师和教学管理者的受控教学工作台”：教师完成计划、观察、倾听、教研和
Word 交付，AI 只提供可编辑建议，业务事实由教师确认并保存。

建议按以下顺序演进：

```text
单园教师效率工具
    ↓
单园教学管理平台
    ↓（权限、隐私、保留/删除和恢复策略验证后）
多园或集团平台
```

近期不以增加孤立页面数量为目标，而是把现有五个教学模块从“能够生成和保存”深化为“能够复用、审核、
归档和稳定交付”。模块化单体仍是当前事实基线；没有真实容量、组织边界或独立部署需求时，不提前拆分微服务。

## 2. 当前业务功能与主要缺口

| 领域 | 当前能力 | 主要缺口 | 方向 |
|---|---|---|---|
| 每日活动计划 | 教案拆分、年龄适配、活动生成、人工编辑、历史、单条/批量 Word、受控单 Patch 确认 | 当前 SHA 的浏览器/MySQL/Word 复验；跨计划复用不足 | 作为主业务线增加周/月视角、方案复用和审核 |
| 游戏观察 | 图片、视觉 AI、观察目标/记录/评价/支持策略、历史、Word | 当前 SHA 的图片、视觉 AI、历史和 Word 复验；跨记录关联不足 | 与幼儿成长档案和阶段总结衔接 |
| 一对一倾听 | 五领域、图片批量导入、指标、评价、合并/分领域/批量导出 | 完整 P8/P8d 人工闭环尚未完成 | 先闭合现有流程，再增加连续跟踪和领域趋势 |
| 自制教玩具 | AI 生成、人工编辑、保存、历史、Word | 与计划和资源复用关系较弱 | 接入教学资源库并支持方案复用 |
| 课程审议 | 教案拆分、调整理由、修订稿、历史、删除、Word | 缺少正式提交、审核、退回、定稿和归档 | 建立可审计的教学审核闭环 |
| Word 与导出 | 五套固定模板、字段映射、图片、差异标红、指标、单条及部分批量导出 | 模板由开发者维护；缺少版本、预览、回滚和统一文档管理 | 建设受控模板中心和统一文档中心 |
| AI 与 Agent | 文本/视觉单次生成；每日计划 4 READ + 2 DRAFT 和本地逐 Patch 确认 | 仅覆盖已冻结的窄场景 | 保持人工控制，按独立 ADR/spec/Issue 决定后续能力 |

横向问题包括：五个模块之间关联较弱；历史记录的搜索、复制、汇总和归档能力不足；教师端比教学管理端成熟；
`teaching_admin` 的跨教师可见和操作范围尚未冻结；业务完成和导出质量指标尚未产品化。

## 3. 业务功能方向

### 3.1 P0：Word 模板中心第一期

目标是把“仓库固定模板”演进为“管理员可管理、仍受契约约束的版本化模板”，优先复用现有五类 exporter。

建议范围：

- 按文档类型上传、校验、预览、启用和停用 DOCX 模板。
- 受控占位符与必填字段校验；拒绝无法识别或缺失关键结构的模板。
- 模板版本、激活版本、修改人、修改时间和回滚。
- 园所名称、Logo、字体、页眉页脚等受控样式配置。
- 使用合成测试数据预览导出；每份导出记录实际模板版本。
- 五类现有 Word 导出逐一接线，并在 Microsoft Word/LibreOffice 中独立验收中文、图片、差异、指标和分页。

第一期非目标：在线拖拽式 Word 编辑器、任意宏/脚本执行、自动修复未知模板、改变现有五类业务字段、Agent
自动选择或修改模板。该方向改变 [ADR-0004](ADR/ADR-0004-ai-and-fixed-word-boundaries.md) 的固定模板契约，
实现前必须新增 ADR，专门取代或细化其中“固定模板权威来源”这一子决策，并冻结文件存储、版本权威、权限、
回滚和验收边界；ADR-0004 的 AI 密钥、教师采用和真实 Word 验收边界继续有效。

### 3.2 P1：统一教学文档中心

- 先统一五类导出物的持久化语义和元数据；当前部分流程直接下载，不能假设所有 `ExportRecord` 路径都对应
  可长期下载的文件。
- 为导出记录补充文档类型、模板版本/hash、文件大小/checksum、存储对象引用和必要状态，再建设列表页面。
- 按教师、班级、幼儿、日期、业务类型、状态和模板版本查询。
- 单份下载、批量导出、ZIP 打包、重新生成和归档。
- 保留文档与业务记录、导出时间、操作者和模板版本的可追溯关系。
- 明确原业务记录删除、模板失效、文件缺失和重新生成时的恢复语义。
- 为后续审核流预留稳定状态模型，但第一期不预建复杂审批占位能力。

### 3.3 P2：教学审核与资源复用

- 教师提交，教学管理员审核、退回、定稿和归档；审核意见与版本留痕。
- 从历史计划复制为新计划，把活动、材料和支持策略收录到资源库。
- 标签、收藏、关键词搜索和受控复制；自制教玩具与每日计划建立显式业务关联。
- 先冻结 `teacher`、`teaching_admin`、`sys_admin` 的读取、覆盖、审核、删除和导出权限矩阵。

### 3.4 P3：幼儿成长档案与管理视图

- 当前没有稳定的幼儿主数据实体，游戏观察和一对一倾听主要保存姓名文本；不得直接按同名字符串聚合档案。
- 将游戏观察和一对一倾听按幼儿形成受控时间轴和五领域阶段总结。
- 由教师人工选择进入档案的材料，不把模型生成内容自动认定为成长事实。
- 增加班级/教师完成情况、待审核和缺失材料视图；指标只保存脱敏事件和结果码。
- 在进入实现前冻结幼儿身份来源、跨教师权限、保留期、删除、导出审批、AI 外发和家长访问规则。

## 4. 当前系统能力与方向

当前已有可信登录会话、三类角色、tenant/user 投影、SQLite/MySQL 与 Alembic、AI Key 加密、提示词版本、
审计、只读 API、Compose/OCI digest 部署框架，以及受控 Agent 边界。系统方向按以下顺序推进：

1. **可靠运行**：完成 Issue #54 的数据库 readiness、Compose 接线、真实 MySQL 故障—恢复矩阵，并让
   digest 部署/回滚以 readiness 作为接流量门禁。
2. **恢复能力**：验证数据库、密钥、必要导出和模板文件的备份/恢复，明确数据库迁移不可自动回滚。
3. **权限治理**：冻结角色矩阵、跨教师访问、审核、导出、删除和管理员操作审计。
4. **文档基础设施**：建立模板元数据、受控文件存储、版本、文档索引、归档和孤儿清理事务边界。
5. **业务可观测性**：记录脱敏的业务完成、耗时、AI 降级、并发冲突和导出质量事件，不保存幼儿正文或图片。
6. **架构治理**：逐步把大型 NiceGUI 页面中的业务编排抽到 service/use-case，统一事务和失败恢复；暂不为
   `services/` 目录虚构已经运行的微服务。
7. **集成演进**：先用真实调用方验收只读 API，再以最小字段、幂等、授权和审计决定是否增加写接口。

## 5. 阶段依赖与交付门禁

```text
现有五模块复验 + R5 readiness/恢复/发布门禁
        ↓
角色权限矩阵 + Word 模板契约 ADR/spec/稳定 RED
        ↓
Word 模板中心第一期
        ↓
统一教学文档中心
        ↓
审核与资源复用
        ↓
幼儿成长档案和管理视图
```

每个产品阶段都必须单独定义用户、角色、数据归属、可见结果、持久化结果、失败恢复和非目标；按
“文档/spec → Issue/任务 → 稳定 RED → 最小 GREEN → 双轴 Review → 当前 SHA 自动验证 → 目标平台人工验收”
推进。方向文档、图谱或历史测试不能替代这些门禁。

## 6. 进入实现前需要产品负责人冻结的决策

1. 第一阶段是否只承诺单园受控部署，以及 `teaching_admin` 是否可以跨教师查看、审核、导出或删除。
2. 模板由谁上传、审批和激活；目标 Office 版本、字体、Logo、图片和分页的签字标准是什么。
3. 模板、导出文件和业务记录分别保留多久；删除、归档、重新生成和备份恢复的权威关系是什么。
4. 幼儿姓名、图片、观察文本和 Word 是否允许跨教师、跨班级或发送到指定 AI，如何取得授权并完成删除。
5. 文档中心第一期只做查询/批量交付，还是同时引入审核状态；两者应避免在一个 Issue 中无限扩张。
6. 何时有真实证据支持多园 SaaS、家长端、写 API 或服务拆分，而不是仅因目录或 tenant 字段提前承诺。
